# 08 — Companion & Device Readiness

## 1. MVP Companion Goal

The MVP Companion proves that StageCore can execute local capabilities on a replaceable Mac/PC without making that machine the Project source of truth.

It does not need the full future provisioning experience yet.

## 2. Minimum Companion Functions

- start as a local agent/service;
- connect to configured Hub;
- present stable Companion identity;
- complete a simple explicit pairing/trust step;
- report agent version and supported capabilities;
- receive one Machine Role assignment;
- receive relevant runtime configuration;
- execute local OSC/MIDI capability where configured;
- report action accepted/failed/timed out;
- report heartbeat/readiness;
- reconnect without replaying the last command.

## 3. Pairing

For MVP, pairing may use a short-lived code generated by Hub and entered/confirmed on Companion or UI. Final PKI/key-rotation details belong to the Security Specification.

Minimum behavior:

- unpaired Companion cannot execute Project commands;
- successful pairing creates trusted identity;
- operator can revoke the Companion;
- revoked Companion cannot regain runtime authority by reconnecting with stale session data.

## 4. Machine Role

MVP needs at least one role model such as `VIDEO-MAIN`.

The user can:

- create/select role;
- assign one trusted Companion;
- see `ASSIGNED / READY / DEGRADED / OFFLINE`;
- release/replace assignment.

Cues target the logical role/alias, not the machine hostname.

## 5. Device/Target Configuration

MVP allows manual target creation for:

- OSC host + port + address/arguments;
- basic HTTP endpoint later in MVP;
- basic MIDI destination later in MVP.

Automatic LAN discovery is optional and must not block implementation.

## 6. Readiness

A target/role can report:

- `UNKNOWN`
- `READY`
- `DEGRADED`
- `OFFLINE`
- `MISMATCH`

Readiness must reflect what StageCore actually knows. A UDP target may be configured and sendable without being verifiably online; UI must distinguish that from verified readiness.

## 7. Acceptance

- New Companion can be paired and assigned a role.
- Cue can target the role and execute through Companion.
- Disconnect changes readiness promptly.
- Reconnect does not duplicate the last Action.
- Replacing Companion does not require editing the Cue definition.
