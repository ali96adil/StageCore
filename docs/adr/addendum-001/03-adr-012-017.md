# **ADR-012 — Performance Recording Archive**

**Status:** Approved Design Direction

**Decision:** يضاف **Performance Recording** إلى Show Session كأصل توثيقي مرتبط بالعرض المنفذ.

يمكن ربط Full Show Recording، زوايا Camera متعددة، Technical Camera، صور، Behind-the-Scenes Documentation، External Storage References وNotes بالـSession الصحيح. يمكن مستقبلًا ربط Cue Timestamps بالتسجيل وإضافة Markers، مثل Cue 24 → 00:31:42.

**Architectural implications:**

- التسجيل Attachment موثق للـSession وليس جزءًا من Critical Show Control Path.
- يخضع التسجيل لسياسة Managed/Referenced/Archive Required المناسبة.
- يجب حفظ Timebase وRecording Identity والعلاقة بالـRuntime Snapshot.
- Ingest أوTranscoding أوAnalysis عمليات P3 مؤجلة خارج Show Mode.

**Open Questions:** Time Synchronization، Metadata متعددة الكاميرات، Privacy/Consent، وسياسة حجم وRetention التسجيلات.

# **ADR-013 — Archive Lifecycle**

**Status:** Approved Design Direction

**Decision:** يعتمد المشروع حالات Lifecycle واضحة: **ACTIVE**، **FINAL**، **ARCHIVED**.

يفحص **Archive Project** اكتمال Project Configuration، Runtime Snapshot، Required Media، Scripts، Plugin Manifest، Rehearsal Data، Final Logs، Notes، Technical Fiche، Machine Roles، Device Mappings، Checksums وPerformance Recordings أوReferences وفق السياسة.

**Architectural implications:**

- النسخة ARCHIVED تاريخية وغير قابلة للتعديل المباشر.
- إعادة الإنتاج تستخدم **Create Revision / Revival from Archive**، مثل العميان — Revival 2028.
- يحتفظ Revival بالنسب إلى الأرشيف الأصلي ويبدأ Revision مستقلة.
- Archive Complete نتيجة تحقق موثقة وليست مجرد نقل Folder.

**Open Questions:** متطلبات FINAL، سياسة إعادة فتح Archive، Retention/Deletion، والتعامل مع Plugins أوFormats القديمة.

# **ADR-014 — Venue Profiles**

**Status:** Approved Design Direction

**Decision:** يفصل StageCore **Show Project** عن **Venue Configuration** عبر Venue Profiles قابلة للحفظ وإعادة الاستخدام.

يمكن لملف Venue أن يضم Projector Mapping، Physical Outputs، Lighting Patch، DMX Universes، Fixture Assignments، Network Mapping، StageNode Placement، Venue-specific Scaling وLocal Equipment Notes.

**Architectural implications:**

- يبقى منطق العرض في Project، بينما يترجم Venue Profile المخرجات المنطقية إلى بنية المسرح الفعلية.
- يمكن للمشروع نفسه امتلاك ملفات مثل Main Theatre 2026 وNational Theatre 2027 وFestival Venue 2028.
- يرتبط Runtime Snapshot بProject Revision وVenue Profile Version معًا.
- أي Capability Mismatch يجب أن يظهر قبل Publish/Preflight.

**Open Questions:** ملكية Profile ومشاركته بين المشاريع، Versioning، وطريقة Merge عند تحديث تجهيزات المسرح.

# **ADR-015 — Logical Lighting Layer**

**Status:** Approved Design Direction

**Decision:** تستخدم Cues أسماء إضاءة منطقية بدل DMX Channel Numbers متى أمكن، مثل Front Wash وBack Wash وStage Left Special وDoor Practical وElevator Light.

يتولى Venue Profile تحويل Logical Lighting Outputs إلى Fixtures/Channels/Universes الفعلية.

**Architectural implications:**

- تطبق Identity Separation على الإضاءة كما تطبق على الأجهزة والمنافذ.
- لا تمنع الطبقة التكامل مع Lighting Console؛ يمكن أن يكون Mapping إلى Console Cue أوGroup أوProtocol Capability.
- يكشف النظام Logical Output غير المعين أوالمعين إلى Capability غير كافية.
- لا يحول القرار StageCore إلى Lighting Console كامل؛ يبقى دوره Logical Lighting + Mapping + Integration.

**Open Questions:** نموذج Color/Position capabilities، دعم Console-native cues، وحدود القيم التي يملكها StageCore مقابل Console.

# **ADR-016 — Lighting Adaptation & Scaling**

**Status:** Approved Design Direction

**Decision:** يدعم Venue Mapping علاقات 1 logical → 1 fixture، و1 logical group → multiple fixtures، وmultiple physical fixtures → logical group، مع Intensity Scaling.

يمكن تعريف Venue Master Scale وPer Logical Group Scale وFixture-specific Limits. مثال: Front Wash = 70% منطقيًا، مع Scale = 1.0 في Venue A و0.72 في Venue B.

**Architectural implications:**

- لا تعدل عشرات Cues بسبب اختلاف قوة أوعدد Fixtures.
- تحتفظ القيم المنطقية بأصلها، ويطبق Scaling في Mapping Layer بصورة قابلة للمعاينة.
- تمنع Limits تجاوز الحدود المعرفة للمكان أوFixture.
- يجب أن يقدم Test/Preview نتيجة التحويل قبل Publish.

**Open Questions:** ترتيب تطبيق Scales/Limits، Color Scaling، وتعامل Mismatch عندما يفتقد المسرح Capability مطلوبة.

# **ADR-017 — Adapt Show to Venue Workflow**

**Status:** Approved Design Direction

**Decision:** يضاف Workflow مستقبلي باسم **Adapt Show to Venue** لنقل العرض بصورة منظمة إلى مسرح جديد أوإعادة تحميل إعدادات مسرح سابق.

**Conceptual workflow:**

1. اختيار Project.
2. اختيار أوإنشاء Venue Profile.
3. اكتشاف أوإضافة أجهزة المكان.
4. Mapping للـLogical Outputs.
5. Projector Reassignment.
6. Lighting Patch / Fixture Mapping.
7. Intensity Scaling.
8. Capability Mismatch Detection.
9. Group Testing.
10. Preflight.
11. حفظ Venue Profile.

**Architectural implications:** Workflow طبقة تنسيق فوق Device Registry وCapabilities وRoles وVenue Mapping، ولا يكتب Cues من جديد. يجب أن تكون كل خطوة قابلة للاستئناف والتدقيق.

**Open Questions:** مستوى Automation المقبول، Validation Gates، وكيفية حفظ Temporary Touring Overrides.
