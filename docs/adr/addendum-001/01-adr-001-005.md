# **ADR-001 — Hybrid Architecture with Hub Authority**

**Status:** Approved Design Direction

**Decision:** يعتمد StageCore بنية **Hybrid Distributed System** يكون فيها **StageCore Hub / Server** العقل المركزي ومصدر الحقيقة الرسمي.

يستضيف الـHub الحالة الرسمية للمشاريع، Cue Engine، Routing، Device Registry، Project Aliases، Rehearsal Memory، Notes، Plugin Configuration، Permissions، Credentials/Secrets، Logs، Runtime Snapshots، Project Vault وحالة النسخ الاحتياطي. النسخة الأولى المستهدفة يمكن أن تعمل على Raspberry Pi أوMini PC، مع بقاء التصميم Hardware Independent.

**Architectural implications:**

- لا يكون Mac/PC هو مكان المشروع الأساسي أوالمرجع النهائي للحالة.
- Clients وCompanions وNodes تستهلك الحالة المنشورة أوتحتفظ بذاكرة تشغيل محدودة وفق ADR-011.
- يجب أن تكون ملكية الحالة، أوامر التغيير، والتزامن مع الـHub صريحة وقابلة للتدقيق.
- Local First يعني أن الـHub يعمل على Stage Network محلية دون اعتماد على Internet، لا أن كل جهاز يصبح مصدر حقيقة مستقلًا.

**Open Questions:** الحد الأدنى لمواصفات الـHub، نموذج High Availability المستقبلي، وحدود السعة حسب عدد المشاريع والوسائط.

# **ADR-002 — Replaceable Mac / PC Companion**

**Status:** Approved Design Direction

**Decision:** ينشأ **StageCore Companion** كتطبيق أوAgent خفيف على macOS/Windows لتنفيذ التكاملات المحلية التي لا يستطيع الـHub تنفيذها مباشرة.

يتولى Companion تكاملات البرامج المحلية، OSC وMIDI المحليين، Keyboard Shortcuts، تشغيل التطبيقات والتحكم المسموح، Scripts المحلية المعزولة، تكاملات Media Playback Software، Local Device Discovery ومعلومات Display/Output.

**Architectural implications:**

- Companion منفذ قدرات محلية وليس مالكًا للمشروع.
- يجب أن يعرض Capabilities وHealth وVersion وحالة الثقة للـHub.
- يجب أن يكون Mac/PC قابلًا للاستبدال دون إعادة كتابة Cues أوRouting.
- لا يسمح لفشل Companion بإفساد الحالة الرسمية؛ يسجل الفشل ويطبق Error Policy وFallback المناسبين.

**Open Questions:** حدود صلاحيات OS، نموذج تحديث Companion، وسياسة Sandboxing والتوقيع على macOS/Windows.

# **ADR-003 — Machine Roles**

**Status:** Approved Design Direction

**Decision:** ترتبط المشاريع بـ**Machine Roles** منطقية بدل أسماء أجهزة الكمبيوتر الفيزيائية.

أمثلة: VIDEO-MAIN، VIDEO-BACKUP، AUDIO، PROJECTION، OPERATOR-01. تتعامل Cue مع الدور: VIDEO-MAIN → Scene 04، ثم يربط النظام الدور بجهاز فعلي موثوق في بيئة العرض الحالية.

**Architectural implications:**

- Machine Role امتداد متخصص لمبدأ Project Logical Identity في v0.2.
- تبديل Mac A بـMac B لا يغير Cue نفسها؛ يتغير Role Assignment فقط.
- يجب دعم Role Transfer، Backup Candidate، وحالة Unassigned/Assigned/Ready/Degraded.
- Preflight يتحقق من أن الجهاز المسند يحقق Capabilities ومتطلبات الدور.

**Open Questions:** هل يسمح بدور نشط على جهازين بالتوازي، وكيف تحسم القيادة عند Failover أوManual Takeover؟

# **ADR-004 — Companion Pairing & Provisioning**

**Status:** Approved Design Direction

**Decision:** يوفر StageCore Workflow آمنًا وسريعًا لربط Mac/PC جديد بالـHub ومنحه هوية وإسناده إلى Machine Role.

التسلسل المرجعي: يكتشف Companion الـHub، ينفذ المستخدم Pairing Code أوQR أوطريقة آمنة مماثلة، يمنح الـHub الجهاز Device Identity، يسند المستخدم Machine Role، يسحب Companion Configuration المطلوبة، ينفذ Preflight، ثم يصل إلى READY.

**Required lifecycle operations:**

- Revoke Device.
- Replace Machine.
- Transfer Role.
- Re-pair.
- عرض Device Trust Status وسجل التغييرات.

**Architectural implications:** يجب فصل اكتشاف الجهاز عن منحه الثقة، وألا تمنح عملية Discovery صلاحية تشغيلية تلقائية. كل اعتماد أوإلغاء أوتحويل دور يجب أن يكون موثقًا.

**Open Questions:** آلية الهوية المشفرة، مدة صلاحية رموز Pairing، تدوير المفاتيح، واستعادة الثقة بعد فقد الـHub.

# **ADR-005 — Role Configuration vs Machine Configuration**

**Status:** Approved Design Direction

**Decision:** يفصل StageCore بين **Project Configuration** و**Role Configuration** و**Machine Configuration**.

- **Project Configuration:** منطق العرض، مثل Cue 21 → VIDEO-MAIN → Scene 04.
- **Role Configuration:** ما يحتاجه VIDEO-MAIN من OSC/MIDI Mappings، Plugins، Shortcuts، Media، Applications وصلاحيات.
- **Machine Configuration:** Paths والأجهزة المحلية وDisplays وAudio Interface وFilesystem وإعدادات OS للجهاز الحالي.

**Architectural implications:**

- لا تدخل التفاصيل الفيزيائية داخل Project Configuration إلا عند استحالة التجريد.
- Role Configuration قابلة لإعادة الاستخدام والتحقق، بينما Machine Configuration محلية وحساسة للبيئة.
- يجب أن يظهر Preflight الفرق بين Requirement غير محقق وMapping محلي مفقود.
- Secrets المحلية لا تنتقل ضمن Project Export غير الآمن.

**Open Questions:** حدود Portable Configuration، ومن يملك Overrides الخاصة بالمسرح مقابل Overrides الخاصة بالجهاز.
